# ИИ-помощник проректора — веб-клиент

Фронтенд для ChatNode: чат с ИИ-помощником проректора.

Vite + React + TypeScript, обычный CSS. Из зависимостей только `react`, `react-dom`
и `@microsoft/signalr` — ни UI-китов, ни CSS-фреймворков, ни стейт-менеджеров.

## Запуск

```bash
npm install
npm run dev
```

Клиент поднимется на <http://localhost:5173> и будет проксировать `/api` и `/chat-hub`
на бэкенд (`http://localhost:5064` по умолчанию). Прокси снимает вопрос CORS —
в дев-режиме всё живёт на одном origin, менять бэкенд не нужно.

Другой адрес бэкенда — через `.env` (см. `.env.example`):

```
VITE_API_TARGET=http://localhost:5064
```

Сборка в статику: `npm run build` → `dist/`. Если раздавать её отдельно от API,
укажите `VITE_API_BASE` и настройте CORS на бэкенде.

## Что где лежит

| Путь                 | Зачем                                                        |
| -------------------- | ------------------------------------------------------------ |
| `src/api/client.ts`  | REST: гостевой вход, refresh токенов, файлы, методички        |
| `src/api/hub.ts`     | SignalR: чаты, сообщения, статусы агента, переподключение     |
| `src/api/types.ts`   | Контракты бэкенда + нормализация ответов                      |
| `src/hooks/useChat.ts` | Всё состояние чата: одна точка, где сходятся REST и сокет   |
| `src/components/`    | Презентационные компоненты                                    |
| `src/styles/theme.css` | Токены дизайна: цвета, отступы, радиусы, обе темы           |
| `src/styles/app.css` | Раскладка и компоненты                                        |

## Как связано с бэкендом

| Возможность                | Куда ходит                                          |
| -------------------------- | --------------------------------------------------- |
| Вход гостем                | `POST /api/auth/guest` (при первой загрузке)         |
| Протухший токен            | `POST /api/auth/refresh` (авто-повтор на 401)        |
| Подключение сокета         | `GET /api/auth/ws-ticket` → `/chat-hub?ticket=…`     |
| Список чатов               | хаб `GetChatList`                                    |
| Создание чата              | хаб `CreateChat` — при отправке первого сообщения    |
| История переписки          | хаб `GetMessages`                                    |
| Отправка вопроса           | хаб `SendMessageToConsultingAgent`                   |
| Прогресс агента            | событие хаба `AiStatusUpdate` → индикатор «думает»   |
| Статус файла               | событие хаба `FileStatusChanged` → тост              |
| Проверка заявки            | `POST /api/chat/{chatId}/files`                      |
| Список положений о гранте  | `GET /api/manuals`                                   |
| Загрузка положения         | `POST /api/manuals/upload`                           |

Форматы файлов заданы валидаторами на бэкенде, клиент их дублирует:

| Что                | Формат  | Ограничения                                    |
| ------------------ | ------- | ---------------------------------------------- |
| Положение о гранте | `.md`   | до 50 МБ, название 4–500 символов              |
| Заявка на проверку | `.docx` | до 50 МБ, сопроводительный текст ≤ 5000 знаков |

## Решения, которые стоит знать

**Тема.** Значение лежит в `data-theme` на `<html>`; инлайн-скрипт в `index.html`
ставит его до первой отрисовки, иначе тёмная тема моргает белым. Все цвета —
CSS-переменные из `theme.css`, компоненты о теме не знают. Пока пользователь не
переключил тему руками, клиент следует за системной.

**Чат создаётся лениво.** «Новый чат» не дёргает сервер — `CreateChat` уходит
вместе с первым сообщением, заголовок берётся из его текста. Иначе в списке
копятся пустые чаты.

**Переподключение своё, а не `withAutomaticReconnect`.** Сокет авторизуется
одноразовым ticket в query-строке, живёт он 30 секунд. Штатный реконнект бьётся
в тот же URL со старым билетом, поэтому в `hub.ts` свой цикл: новый билет →
новое соединение, задержки 1с → 2с → 4с … до 15с.

**Markdown свой, на 150 строк.** Ответы модели приходят с разметкой, а тащить
`react-markdown` ради заголовков и списков — это +40 КБ. Текст экранируется до
сборки HTML, ссылки пропускаются только `http(s)`.
